## Changes

- **Status bar and title hit area:** Clear fullscreen, layout-under-system-bars, no-limits and translucent-bar flags; ask the window decor and content to fit system insets, restore contrasting status/navigation icon colours, request fresh insets. The surface should be laid out in the activity's content region rather than under the system clock. This is a code-level correction, **not a phone-verified fix**; the previous non-fullscreen theme and icon changes alone failed on the user's device.
- **Purple bands:** `PageStage::setSource` now clears selected glyph indices, search-hit state and annotation/draft state before opening a different tab. Previously indices from PDF A could be painted as selection rectangles on PDF B. A tab-switch regression asserts that the selection is cleared. This is a plausible explanation for the screenshot, not proof that every purple band has this cause; if bands persist in the same PDF after a clean launch, a sample PDF is needed.
- **Blank thumbnails / slow cold pages:** Focused-page dimensions now resolve before that page's preview; the worker prioritises the visible-page proxy and then visible tiles while allowing one nearby small thumbnail after four sharp tiles, instead of starving the thumbnail strip. Rendering still occurs on the PDF worker; no new offscreen speculative prefetch was introduced. This is a scheduling change, not a measured on-device throughput claim.
- **Touch control:** Android historical MotionEvent samples carry their actual OS timestamps to gesture velocity estimation. Samples less than 2 ms apart do not set velocity; instantaneous/fling velocity is bounded. One-finger page pan has touch slop and a vertical lock, so diagonal drift cannot move the PDF horizontally. Two-finger pan only moves sideways on deliberate horizontal travel. Flings decay sooner and stop on bounds. Sidebar-list fling is also bounded, and a paused finger no longer launches an old fling. Stationary page touches stop driving frames after the long-press opportunity ends.
- **Touch scrollbars:** The PDF canvas's vertical bar and the common ScrollView bar (used by the thumbnail list and other scrollable panels) now have enlarged touch targets, thumb/track drag handling and pointer ownership until release/cancellation. A bar drag cannot accidentally pan or select the page behind it.
- **Existing popup/render work retained:** The prior pass avoids chrome-only repaint of a popup covering the PDF and provides a bounded low-resolution visible-page preview while 512-device-pixel sharp tiles fill. This pass did not produce a physical-device battery, RAM, frame-time or zoom benchmark.

## Verification and limits

- Linux headless build completed; CTest **18/18 passed**, including the updated navigation/selection and mobile-input suites (touch bar, vertical-only drag, pinch and annotation checks).
- Android `:app:assembleDebug` and `:app:lintDebug` both completed successfully in the clean temp-only rebuild. The APK passed ZIP integrity and was byte-compared with the Gradle output. Both native ABIs were checked on the immediately preceding build of the same source; this temp-only rebuild did not rerun the ABI manifest dump. Its hash above differs from the original regressed APK's `46941368...`.
- The sandbox has no real Android phone or usable emulator (`/dev/kvm` absent), so **status-inset positioning, clicks, popup smoothness, zoom flash, thumbnail latency, CPU, RAM and battery consumption are not confirmed on the user's device**. A build/lint check does not establish runtime behaviour.
- The screenshots alone cannot diagnose a PDF-specific outline encoding, missing glyph/font or malformed bookmark title. PDFium already returns bookmark titles as UTF-16, which Folio converts to UTF-8 for common BMP characters; the current converter substitutes replacement characters for supplementary-plane surrogate pairs. No affected PDF was supplied, so outline titles have not been confirmed fixed. Request the original PDF or a shareable redacted reproduction if they remain garbled.
