# Responsive reader / Home corrections — 2026-10-17

Changes in this round (relative to the prior `folio-android-full-debug.apk`):

1. The stationary non-text 0.5-second tool palette is shared by touch and pen regardless of viewport width or editing mode. Desktop PDF right-click opens the same pinned palette immediately. X11 XI2 touch already delivered real touch events; Windows now routes WM_POINTER touch/pen IDs, pressure and tilt and suppresses duplicate synthesized mouse clicks. Mouse right-button release does not also select the PDF.
2. A short-height landscape phone retains compact phone chrome and bottom sheets instead of accidentally switching to a two/three-column tablet layout solely because its width grew. A normal-height tablet keeps its normal breakpoint. Home cards remain in a scrollable grid; the large Continue reading hero is hidden on compact Home.
3. Home no longer paints hero/search copy above Settings popovers. Settings is scrollable and height-limited on short windows; popovers clamp to the viewport. The redundant subtitle is removed; the greeting uses the OS local clock. A gear icon replaces the sun-like Settings drawing.
4. Hover tooltips are not armed by touch. They expire automatically, vanish when the owner/screen hides, and are cleared before a tool button is destroyed or a screen changes. Toast dismissal remains automatic.
5. The command bar allocates space from both ends with a guaranteed tool-dropdown slot. Selecting a mark collapses Hand/Select into that dropdown immediately; controls that do not fit remain available in the inspector rather than overlapping. This logic is viewport-size driven rather than Android-only.
6. Left-sheet pages, outline, Notes, Layers and thumbnail actions now use the sheet's *actual* height, reserve room for the bottom gesture strip, and remain scrollable. Short landscape sheets grow upward to keep a useful viewport.
7. Theme change is 700 ms cubic ease-in-out: dark reveals outward and light contracts inward, without a coloured outline or gradient on the UI reveal. Android's system/status/navigation bar backgrounds receive the same timeline as a uniform colour (their system-drawn glyphs switch contrast halfway). Actual bar rendering/compositing remains subject to the device/OEM.
