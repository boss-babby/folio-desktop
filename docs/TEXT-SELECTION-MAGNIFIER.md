# Touch magnifiers and legible PDF highlights — 2026-10-16

## Research and rendering

- W3C CSS Pseudo-Elements Level 4, §3.6.3: browser highlights draw their backgrounds and then redraw the active text above them. This is the desirable **background-tint, crisp-foreground** effect, but separately retypesetting PDF glyphs would misrepresent embedded fonts, cropped/rotated pages and scans. https://www.w3.org/TR/css-pseudo-4/#highlight-painting
- Nutrient’s annotation blend-mode guide describes Multiply for legibility of markup covering text; the PDF Association describes background/foreground blending in PDF transparency. https://www.nutrient.io/guides/ios/annotations/annotation-blend-modes/ ; https://pdfa.org/20-years-of-transparency-in-pdf/
- Folio keeps PDFium’s original glyph pixels: **Multiply** warm translucent marks into light/sepia paper (black ink remains black); **Screen** into dark/inverted paper (white ink remains white). Blend state is reset after each mark. The same approach applies to active selection, search fills and saved highlights. Fine borders and slightly rounded per-line text-selection rectangles are retained; no PDF glyphs are re-created from extracted Unicode.

## Two touch-only loupe workflows, one saved switch

- On Android the **Selection & highlighter magnifier** preference starts ON. The existing saved toggle in the Reader’s right Display inspector now controls both workflows; desktop starts OFF.
- **Text selection:** holding a selected word or dragging a selection handle shows the actual cached PDF pixels and the *same amber text bands* as on the viewport. The already-calculated page selection rectangles are reused inside the 2x loupe, without a second text traversal. Selection dots still point upper-left/lower-right, with 44dp invisible touch diameters. The markup popup waits for finger release so it cannot cover the loupe.
- **Annotate → Highlight (the free-form horizontal highlighter, not text-selected markup):** touching the page immediately opens a cached-pixel loupe with a short prospective highlight strip **before any mark is drawn or saved**. Its band uses the same annotation color, opacity, blend and page-relative **thickness** as the real highlighter, at the current page zoom (the default is 0.026 page-height; the six width options now scale both the document band and prospective preview). Before the first intentional sideways stroke, moving the finger up/down (and through small sideways jitter) repositions the still-empty draft and the loupe without colouring the PDF. Once horizontal displacement passes a 10dp touch slop, the **last previewed row locks** and the first stroke begins; even if that first sideways event is diagonal, its vertical component cannot jump the line. Subsequent drag samples follow the stroke’s clamped X endpoint while vertical finger wobble no longer changes the row. The loupe shows the actual draft plus a short prospective strip ahead of its active edge; near the top edge it docks to the side rather than disappearing. Vertical-only movement followed by release commits no mark. Mouse/pen highlighter behaviour remains immediate. Only this particular tool gains a drawing loupe; pen, shapes, eraser and mouse do not.
- Both loupes have **no Widget or pointer target**, reuse *resident* PDF proxies/tiles without submitting new raster work, disappear on release/cancel/pinch/toggle-off, and do not modify tile scheduling. If page pixels have not arrived yet, they do not show a blank bubble. Two-finger pinch cancels an unfinished highlighter draft and its loupe.
