# Folio versus `MEMORY_AND_PERFORMANCE.md`: code-based audit

**Scope:** The attachment describes a different implementation despite its title: it cites `app/desktop/src/app.cpp`, `session.cpp`, `SDL_WaitEventTimeout`, `Input::probes`, and `core/src/pdf/pdfium_engine.cpp`. Folio's active native reader uses `folio-ui/shell/NativeShell.cpp`, `folio-ui/screens/ReaderScreen.cpp`, `folio-ui/components/PageStage.cpp`, and `folio-engine/pdfium/`. The attachment's statuses, CPU ticks, and 134.6 MB RSS are **not measurements of this Folio checkout**. This is a source review, not a new Windows/Android runtime benchmark. This pass adds non-blocking retirement of closed PDF tabs, hover-change filtering and current-viewport tile protection. The resulting source passed 18/18 Linux CTest suites and produced a new Android debug APK (assembleDebug and lintDebug). Neither result establishes the attachment's performance numbers or substitutes for native Windows/Android runtime testing.

Legend: **Yes** = present in the active native-reader path; **Partial** = similar code but with substantive exceptions; **No** = not present; **Unverified** = code exists but runtime/result has not been established.

A regression checks eventual source release; no deliberately slow-render latency measurement has been made. | **Partial: tab close improved; quit/latency unverified** |

Small thumbnails still use separate whole-page raster requests. Old tiles/thumbnail proxies may remain until evicted or idle-pruned. | **Yes for current main canvas** |
| Tile key includes page, zoom, rotation, theme and location | Folio's source tile key is `(page, device width, tile x, tile y)`; tint is applied on blit and view rotation is handled by the stage. | Per-tab worker; visible first; queued cancellation | One `PdfiumWorker` thread per source. Visible tile queue is ahead of thumbnails, text and metadata; export jobs are ahead of tiles. On each full visible frame queued tiles are replaced; tab suspension clears queued renders/text, and an epoch discards late results. A synchronous PDFium render already in progress finishes. | **Yes, with export/in-flight exceptions** |
| Speculative prefetch and `dropPrefetch` on idle/scroll | The **active native reader does not submit speculative tile prefetch**; it submits intersecting tiles only. `dropQueuedTiles` removes superseded queued visible work. There is no active `dropPrefetch` equivalent to evaluate. | **No prefetch; dropping it is inapplicable** |
| Three-second idle pruning and heap trim | `NativeShell` runs a one-shot pass after three seconds without input. `PdfiumPageSource::trimIdle` releases tiles and thumbnail rasters not touched in the last frame and distant text; Skia's copied image/raster caches are cleared. glibc uses `malloc_trim(0)`; Windows attempts `HeapSetInformation(..., HeapOptimizeResources, ...)`; Android has no corresponding OS heap-trim call here. Folio does **not** call `SkGraphics::PurgeAllCaches`, `SetProcessWorkingSetSize`, or explicitly prune recent-file thumbnail assets. Thumbnails used in the last frame remain in the source. | **Partial** |

Events are wired for Win32 size-minimised, X11 unmap, and Android term-window. In-flight export/render CPU work need not stop. | **Mostly implemented; native runtime unverified** |
| Event loop sleeps / zero CPU at rest | After the one-shot cleanup, native `waitEvents(-1)` blocks when no work/frame is pending, with a worker wake callback. During background work it still checks every 50 ms on desktop or 100 ms on Android, and animations keep painting. There is **no Folio process-CPU measurement** proving 0%; do not import the attachment's result. The loop does not wake repeatedly every three seconds after trimming. | **Mechanism yes; numerical claim unverified** |
| Hover redraw only on recorded geometric-probe boundary crossing | Folio does **not** have `Input::probes` / `pointerCrossedHover`. `FolioApp::pointer` and the router avoid many unchanged-hover frames; this pass makes `ThumbnailList` and `OutlineList` return a change only when the hovered item changes (including crossing thumbnail columns), with direct regression checks for unchanged moves and first leave. `NativeShell` still resets the three-second idle deadline for **every** pointer move: movement is input even when it does not redraw. | No fixed cap / adaptive byte budget | Folio does not use 256-tile/160-thumbnail **entry-count** caps. ## Remaining work for this low-memory/performance pass

Checklist reflects **the current source and rebuilt APK**, not the earlier documentation-only audit. Checked items have code and Linux regression coverage; unchecked items are incomplete or need target-device measurements. The viewport-tile, per-tab source, and one-shot idle mechanisms were already present; they were not reimplemented to mirror the attachment's SDL/RAII class names.

### A. Code and regression checks still needed

- [ ] **Finish exceptional opens and verify slow-work shutdown.** Closed PDF sources now retire on owned background futures, with pending export results held until collected and no detached window callbacks. The navigation regression checks that a closed tab's worker is eventually freed. Remaining: route non-prepared `ReaderScreen::loadPath` fallbacks through the existing background-open path without breaking page-operation reloads; run a deliberately slow in-flight render/close timing test and verify title-bar quit does not wait excessively (owned futures still join at shutdown). **Accept when:** those exceptional paths remain responsive and the last document/thread are released.
- [x] **Hover-change filtering in both navigation panels.** Unchanged moves/second leaves no longer request a redraw; crossing outline rows or thumbnail columns does. Direct pointer regressions pass. Drag/panning still enters `ScrollView` first. **Not claimed:** target-platform continuous-hover paint counts or CPU measurements. The attachment's geometric `Input::probes` API is not required.
- [x] **Visible-tile eviction under source-cache pressure.** LRU now protects the current-frame and requested viewport tiles. A real PDF 49-tile/48 MiB test completes the entire viewport instead of cycling through evicted tiles; existing zoom/idle/suspension tests pass. The source byte budget is **soft for an oversized visible viewport**, and independent Skia/GPU budgets can still evict copied images. The native idle timer retains its three-second *since last input* semantics; no target-platform memory/paint measurement is implied.
- [ ] **Minimise/restore and in-flight work.** Exercise Windows `WM_SIZE`, X11 unmap and Android window teardown/restore with active tile rendering and export. Verify decoded source caches, copied Skia images and the full-window scene are released, the document remains usable, and the next frame correctly recreates on-screen tiles. Do not call GPU APIs after an Android EGL surface is gone. **Accept when:** no crash, leak, blank restore or export corruption appears on the target platform. No result from an old tab may repopulate its visual cache.
- [ ] **Cross-tab PDFium concurrency review.** The normal reader does not make the attachment's direct UI-thread PDFium calls, but distinct tab workers may run concurrently. Stress several tabs doing render/text/outline/export while switching and closing; check the actual PDFium build's thread-safety contract before deciding whether a library-wide lock or another ownership change is necessary. **Accept when:** no UI-thread PDFium access, no unsafe concurrent access or hangs, and visible tile scheduling remains responsive.

### B. Measurements and release verification still needed

- [ ] **A Folio-specific baseline and comparison.** On an actual target system, record peak and settled RSS (or the platform's comparable process-memory metric) for one four-page PDF and several large PDFs: after opening, switching tabs, three seconds idle, minimising, and restoring. Record CPU over an idle interval *after* cleanup and during a repeatable five-second hover sweep, plus frame/paint counts. Report OS, display resolution, DPR, renderer and sample-file details. **Accept when:** numbers are recorded for Folio, not inferred from the attachment; 134.6 MB is labelled solely as the other app's observation, not a Folio target achieved by code inspection.
- [x] **Rebuild and verify Linux + Android for this source.** The final Linux build passed 18/18 CTest suites, including navigation hover, tab disposal, viewport-pressure and retained redraw tests. Android `assembleDebug` and `lintDebug` succeeded; after the subsequent mobile popup/touch/preview/system-bar pass, `/home/user/folio-android-updated-debug.apk` was rebuilt again as a 38,276,054-byte APK (SHA-256 `469413682db50624369b9993b0fdd53315107397bf4b7b0af030ffdfb2831df0`), checked byte-for-byte against Gradle output, ZIP-checked, and inspected for both `arm64-v8a` and `x86_64` native libraries plus the activity manifest. See `MOBILE-RENDER-TOUCH-FIXES.md` for the new pass. The build artifacts and downloaded toolchains are disposable, not deliverables.
- [ ] **Native runtime release gate.** Verify tab close, hover, minimise/restore and multi-tab work on a Windows GUI build and a physical Android device. This environment has no runnable Android emulator or Windows GUI; build/lint/inspection are not device-runtime validation.

### C. Not automatically required in this pass

- **Speculative prefetch:** the active reader does not do it, so there is no `dropPrefetch` bug to fix. Add prefetch only if a measured scrolling case needs it, with visible-first scheduling and idle/tab-switch cancellation.
- **Eliminating every fixed budget:** Folio already uses fixed *byte* budgets rather than the attachment's 256/160 entry caps. A memory-pressure-responsive aggregate budget is a separate design choice; do not claim it exists, or remove all bounds without a replacement. If adaptive budgeting is made a requirement, scope and test it explicitly.
- **Literal `PdfiumPage` RAII, SDL hover probes, PNG export, and Windows working-set calls:** those are details of the attached implementation, not evidence of missing Folio features. RAII could strengthen exceptional cleanup, but the active worker currently closes its page after each job. `SetProcessWorkingSetSize` or `SkGraphics::PurgeAllCaches` should be evaluated for safety and benefit rather than copied blindly. No rendered-page compression, disk cache, or cross-tab pixel sharing is planned.
